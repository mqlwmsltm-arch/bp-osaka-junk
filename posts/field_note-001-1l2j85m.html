Lightsail CPU 크레딧 3분 전에 터지는 AMI 조합 - 상수 노래방 추천 시스템에서 배운 교훈

500만원 청구 내역을 보고서야 깨달았다. 프리티어 계정으로 돌리던 상수 노래방 추천 API 서버가 Lightsail 인스턴스 한 대에서 터지고 있었던 거다. 근데 문제는 CPU 크레딧이 바닥나기 직전 커널 패닉이 먼저 발생한다는 점. AMI 조합이 원인이었다.

조건 분기: t3.micro vs t3a.micro

내가 확인한 건 두 가지 팩트다. 첫째, CPU 크레딧이 10% 미만으로 떨어지면 t3.micro + 특정 Amazon Linux 2 AMI 조합에서 패닉이 3분 내로 온다. 둘째, t3a.micro + Ubuntu 20.04 조합에서는 같은 크레딧 상태에서도 커널 패닉이 발생하지 않았다. 차이는 CPU 제조사와 ACPI 인터럽트 핸들링 로직 차이였다.

이걸 발견한 건 우연이 아니다. 노래방 추천 시스템이 피크 시간에 CPU를 폭발시키고, 크레딧이 소진되기 직전마다 인스턴스가 멈췄다. CloudWatch에서 CPU Credit Balance가 0.5 미만으로 떨어질 때 syslog에 "kernel panic - not syncing: Fatal exception in interrupt"가 찍히는 패턴을 봤다. 3분이라는 숫자는 내가 스톱워치로 직접 측
